## История прогонов до `bb68ed2`

Число исходников, пути к логам и номера строк ниже относятся к прежним срезам.

### Подтверждённые результаты первого прогона

- Базы Release и Debug содержат по 23 записи для 22 исходников. Проверены каталоги, C11, макрос POSIX, параметры профилей и флаги санитайзеров. Apple clangd построил AST серверной сессии и завершил `--check` с нулём ошибок.
- Serena 2.1.0 проиндексировала 34 файла на clangd 19.1.2. В тесте того же MCP stdio-подключения проверены определение `protocol_parse_frame`, объявление в заголовке, переход из места вызова, ссылки из клиента и сервера, обзор символов сессии.
- Joern подтвердил прямые вызовы `protocol_parse_frame` из `on_read` и `session_on_read`. Проверены список функций, исходящие вызовы диспетчера, файловые операции, AST, CFG и data flow. Запрос отсутствующей функции завершился кодом 1.
- Локальные Release, ASan/UBSan и TSan прошли по шесть модульных тестов. Cppcheck, clang-tidy и Clang Static Analyzer выполнились с диагностикой. ShellCheck для новых скриптов прошёл.
- Cppcheck указал на непроверенный результат `strdup` перед `strlen` в клиенте и непроверенное выделение буфера в ECC-тесте. Clang Static Analyzer показал потенциальные утечки на ранних выходах в ECC-тесте и бенчмарке. Cppcheck обозначил `log_stream`, `log_file`, `log_stdout` как кандидатов на неиспользуемый код в данной сборке. ECC используется модульным тестом. Эти сообщения не являются основанием для удаления кода. [Клиент](../../client/src/main.c#L1338), [ECC-тест](../../tests/test_ecc.c#L29), [бенчмарк](../../tests/benchmark.c#L42), [логирование](../../server/src/logging/log.c).

- В Ubuntu 24.04 ARM64 прошли локальные команды CI. CMake Release и ASan/UBSan прошли по 8 тестов, Autotools прошёл 6 тестов, обе сборки установились в staging. Форматирование, ShellCheck и clang-tidy из workflow завершились с кодом 0. Версии гостевой среды — GCC 13.3.0, CMake 3.28.3, Ninja 1.11.1, LLVM 18.1.3, liboqs 0.15.0. Удалённый GitHub Actions в этой ветке не запускался.
- CodeQL 2.27.5 захватил **22 из 22 исходников**. Телеметрия извлечения показывает 23 успешных вызова компилятора и ноль сбоев. В Linux выполнены 98 запросов. В SARIF 14 диагностик, среди них TOCTOU при установке режима файлов, политика прав при создании и недоверенные пути. При просмотре надо учитывать границы доверия CLI: путь из аргумента или окружения сам по себе не подтверждает уязвимость. Замечание о времени выставления прав на закрытый ключ совпадает с пунктом P8 аудита. Лог изолированного прогона (`out/analysis/linux-codeql.log`), SARIF (`out/analysis/linux/codeql.Msad1w/results.sarif`).

### Прогон рабочего NASLUKS

На macOS CMake Release прошли 8 тестов. В Ubuntu ARM64 прошли CMake Release и ASan/UBSan по 8 тестов и Autotools `make check` с 6 тестами. Профиль Colima использовался для сборки и функциональной приёмки. Замеры на целевом NAS и испытание потери питания остаются открытыми.

Локальный `static.sh` по-прежнему возвращает ненулевой статус. Clang-tidy 23 сообщает о битовых операциях со знаковыми типами, Cppcheck — о возможном разыменовании нулевого указателя в ECC-тесте, Clang Static Analyzer — об утечках на ранних выходах в тесте ECC и бенчмарке. Диагностики (`out/analysis`).

### Прогон запуска, ключей и восстановления

CMake Release на macOS и Ubuntu ARM64 прошёл 9 тестов. Linux Autotools прошёл 7 тестов, Linux ASan/UBSan — 9. Новый `integration_lifecycle` запускается в обеих системах сборки и проверяет запуск, конфиг, PID, лимиты, keygen и установленный шаблон `nasfsctl` на временном префиксе. Интеграционные прогоны также форсируют короткие записи PUT и GET и проверяют сохранность прежнего файла. Актуальная граница покрытия приведена в [REFACTOR_PLAN.md](../../REFACTOR_PLAN.md).

Проверка стиля по командам CI в Linux прошла после замены трёх вызовов `strcpy` в хранилище и сессии. `clang-format --dry-run --Werror`, `clang-tidy --warnings-as-errors='*'`, ShellCheck и `git diff --check` завершились успешно. Это локальный прогон команд CI.

Linux-проверка аварии при создании мастер-соли использует тестовую библиотеку `tests/fault_injection.c` только в процессе отдельного клиента. Проверены SIGKILL непосредственно до и после успешного `linkat`, состояние соли на диске и побайтовый PUT/GET после перезапуска. Сценарий прошёл через CMake Release, ASan/UBSan и Autotools. Он проверяет остановку процесса при работающей файловой системе.

Linux-инъекции файловых ошибок подменяют только вызовы libuv для выбранных тестовых файлов. Покрыты отказ чтения источника PUT, отказ закрытия временного PUT, ошибка чтения серверного заголовка GET и отказ закрытия локального временного GET. Задержка завершений записей насытила очередь PUT ровно до четырёх запросов. Передача завершилась с побайтовым совпадением после GET.

Очередь PUT проверена при SIGINT клиента с четырьмя удержанными завершениями и SIGTERM сервера с четырьмя заблокированными файловыми записями. Инъекция запирает только записи временного объекта в изолированном процессе Linux. Для остановки сервера тест выпускает блокировку после отключения клиента, затем проверяет чистый выход, PID-файл, отсутствие staging-файлов и побайтовый GET после перезапуска. Отдельный временный юнит systemd в Ubuntu прошёл запуск, PUT, перезапуск, GET и остановку. [Сценарий systemd](../../tests/test_systemd.sh).

При четырёх заблокированных записях отдельно проверен `ClientTimeout 2`. Таймер закрыл соединение без SIGTERM. После снятия блокировки сервер освободил ресурсы, удалил временный PUT и выдал прежний файл в следующем GET. Прокси также проверяет обрывы на всех четырёх сообщениях установки канала и на AUTH_ACK.

Прокси обрывает PAKE перед доставкой PAKE_HELLO, PAKE_RESPONSE, доказательства AUTH и AUTH_ACK. Проверяются отсутствие файловых запросов и сохранность назначения. Linux также проверяет SIGTERM сервера при заблокированном открытии временного PUT и чтении первой записи GET. После снятия блокировки сервер завершает запрос, очищает ресурсы, а клиент сохраняет прежний объект или назначение. GET после перезапуска совпадает с исходником.

`integration_lifecycle` удерживает чтение конфигурации через FIFO, проверяет SIGINT и SIGTERM до создания PID-файла и затем запускает сервер нормально. `integration_encryption` в Linux удерживает `renameat` после принятого PUT_DONE. SIGTERM оставляет предыдущий файл доступным до переименования и завершает сервер после публикации. После перезапуска GET сверяет новую версию. До подтверждения клиент может получить обычный успех или неизвестный исход, если подтверждение не дошло.

Перед ревью добавлены контрольные точки запуска listener, полный перебор 36 сочетаний файловых алгоритмов и отмена пакетов на задержанном втором элементе. Linux ASan/UBSan прошёл 9 из 9, Autotools — 7 из 7. Linux CMake Release прошёл целевые сценарии запуска и передачи, macOS CMake Release — расширенную матрицу алгоритмов. Проверки clang-format, clang-tidy по параметрам CI и ShellCheck прошли.

### Проверка рабочей копии после ревью 80a63a5

- macOS CMake Release и ASan/UBSan прошли по 9 тестов. Ubuntu ARM64 CMake Release и ASan/UBSan прошли по 9, Autotools — 7. Linux-инъекции подтвердили параллельный GET при остановленном чтении префикса и при остановленном переименовании PUT. После SIGKILL проверяются наличие staging до перезапуска, его удаление после перезапуска и содержимое ранее опубликованного файла. Запуск второго сервера при удержанном переименовании сохраняет staging первого.
- В Ubuntu пользовательский менеджер systemd запустил копию установленного юнита с drop-in для ключей. Проверены совпадение PID-путей юнита, конфига и `nasfsctl`, PUT, перезапуск, побайтовый GET и остановка. CMake и Autotools также проверены с отключённой установкой systemd.
- Linux clang-tidy с параметрами CI, clang-format изменённых C-файлов, ShellCheck интеграционных сценариев и `git diff --check` завершились успешно. Сводный анализ macOS вернул замечания, в том числе clang-tidy на Linux-фикстуре и Cppcheck в ECC-тесте. Логи macOS (`out/ref-static`).
- Linux CodeQL выполнил 98 запросов с покрытием 23 из 23 исходников из базы CMake. SARIF содержит 12 диагностик по путям и правам создания файлов. Отдельный прогон GitHub Actions и замеры на целевом NAS не выполнялись. Лог CodeQL (`out/ref-codeql-final.log`).

### Чистая установка и I/O открытия после повторного ревью

- macOS и Ubuntu ARM64 CMake Release и ASan/UBSan прошли по 9 тестов. Linux-инъекции проверили отдельное соединение при задержке заголовка PUT, заголовка GET и слота GET, короткий I/O на всех трёх путях, отказ постановки открытия, обрыв клиента и остановку сервера. Linux Release (`out/ref2-linux-release.log`), Linux ASan/UBSan (`out/ref2-linux-asan.log`).
- Чистая копия из индекса собирается CMake. Обе системы установки создают каталог из поставляемого `StorageDir` в пустом префиксе. Проверена установка с отключённым systemd. Архив `make dist` содержит шаблон, четыре NASLUKS-фикстуры и заголовки для сборки. Linux Autotools прошёл 7 тестов из исходников и 7 из распакованного архива. Установленные юниты обеих сборок прошли запуск, PUT, рестарт, GET и остановку с путями из поставляемых конфигов. Чистая копия (`out/ref2-clean-index.log`), архив Autotools (`out/ref2-auto-dist-final.log`), CMake systemd (`out/ref2-systemd.log`).
- Linux clang-tidy с параметрами CI, clang-format изменённых C-файлов, ShellCheck интеграционных сценариев и `git diff --check` прошли. Бенчмарк выполнил 30 комбинаций размера, шифра и направления с медианой трёх замеров, проверкой байтов GET и включённым выводом мастер-ключа Argon2id. SFTP пропущен из-за отсутствия доступного доверенного SSH-входа. Лог бенчмарка (`out/ref2-benchmark-final.log`).

### Подготовка индекса после замечаний по запуску

- CMake Release и ASan/UBSan прошли по 9 тестов на macOS и Ubuntu ARM64. Autotools из чистой копии индекса прошёл 7 тестов. Обе сборки установлены в пустые префиксы. Проверены установленный каталог хранения, состав архива Autotools и отключение установки юнита в Autotools. Локальный сценарий запуска проверяет `nasfs_server` без аргументов и приоритет явного конфига. Linux Release (`out/ref3-linux-release.log`), Linux ASan/UBSan (`out/ref3-linux-asan.log`), Autotools (`out/ref3-auto.log`).
- Linux-тесты проверили очистку после SIGKILL, второй сервер с обычной блокировкой, отказ эксклюзивной блокировки с `EBADF`, отказ всех блокировок с `ENOTSUP` и подстановку типа NFS. При двух последних сценариях обычный второй сервер удалил осиротевший staging и сохранил активный staging из исключённого пространства имён. Настоящий NFS-стенд не использовался.
- Установленный CMake-юнит прошёл запуск, PUT, перезапуск, GET и остановку. При инъекции отказа запуска и отказов cleanup-команд systemd конфиг восстановился до `daemon-reload`, временный каталог удалился, исходный код 42 сохранился. systemd (`out/ref3-systemd.log`).
- Linux clang-tidy с параметрами CI, clang-format, ShellCheck интеграционных скриптов и обе проверки `git diff --check` прошли. ShellCheck бенчмарков по-прежнему выдаёт диагностику, категории сверены с HEAD. ShellCheck (`out/ref3-shellcheck.log`).
